# 知乎 V1：浏览器登录与专栏接入

## 已交付范围

- 知乎作为正式平台进入账号中心，与小红书、公众号账号相互隔离。
- 管理员可直接打开内置 Chromium 登录知乎，不需要申请 OpenAPI 资格，也不需要填写 Token 或访问密钥。
- 每个知乎账号使用独立的持久化浏览器目录，登录 Cookie 只保存在团队主机。
- 人工创建知乎选题后，可沿用认领、AI 创作、Humanizer、版本记录、文本审核和审计日志。
- 知乎专栏使用文本审核；审核快照冻结标题、正文、标签、内容类型和版本。
- OpenAPI 代码仅保留为已获批账号的高级后备能力，不作为普通用户入口。
- 知乎 SEO 和公众号共用文章搜索与正文抓取能力，但各自保存关键词、评分、归档与转选题状态。
- 选题搜索由用户主动输入关键词，可按时间和勾选的文章站点筛选外部文章；公众号来源使用 `mp.weixin.qq.com` 定向搜索。
- 搜索通过自托管 SearXNG 的 JSON 接口发现文章；正文验证成功后才能转入既有选题、认领、创作、审核和发布链路。

## 配置文章搜索

运行平台前设置 `SEARXNG_URL`，指向团队自托管的 SearXNG，例如 `http://127.0.0.1:8080`。SearXNG 必须启用 JSON 输出格式。若未设置，开发环境会尝试使用该本机默认地址，但页面会明确显示“使用本机默认地址”，不会伪装成已经配置成功。

文章搜索结果按规范化 URL 去重，同一篇正文只缓存一次；知乎和公众号的研究记录由平台关联表隔离。微信文章优先解析 `#js_content`、公众号名称和发布时间。通用正文解析只处理公开 HTTP/HTTPS 文章，拒绝本机和私网目标；正文不足的结果不返回到界面，也不能转入创作。

## 首次登录

1. 管理员进入“账号管理 → 知乎”，添加一个知乎账号记录。
2. 点击账号卡片上的“登录知乎”。
3. 系统打开独立的 Chromium 窗口，在知乎官方页面完成扫码或其他正常登录步骤。
4. 登录成功后回到多平台内容运营，点击“我已登录，完成绑定”。
5. 系统检测到知乎登录 Cookie 后，将账号标记为在线。

浏览器资料保存在 `runtime/platform-accounts/<账号 ID>/zhihu-profile/`。开发版位于项目数据目录；安装版位于团队主机的 `~/Library/Application Support/红薯台/` 下。该目录会进入管理员主动创建的备份，但不会进入 Git 仓库、源码包或出售的安装包。

## 团队模式

- 只有团队主机上的管理员负责登录和维护知乎登录态。
- 成员电脑不启动知乎浏览器，也不保存知乎 Cookie。
- 成员通过现有团队工作流进行认领、创作和审核。
- 浏览器窗口关闭后，持久化目录仍保留；若知乎会话失效，管理员点击“重新登录知乎”即可恢复。

## 发布状态

审核通过的知乎专栏会进入知乎自己的发布列表。发布员确认后，系统使用同一账号的持久化浏览器打开 `https://zhuanlan.zhihu.com/write`，填写冻结的标题和正文并执行发布。

只有页面跳转到 `https://zhuanlan.zhihu.com/p/<文章 ID>` 才标记成功并保存文章地址。发布按钮尚未点击时的错误可以修复后重试；发布按钮已经点击但结果无法确认时会进入“发布结果待核验”，必须先到知乎确认，避免重复文章。

失败诊断截图保存在对应账号的 `zhihu-profile/publish-failure.png`，仅留在团队主机。知乎页面结构变化、短信验证或账号风控仍可能要求管理员人工处理。

## 未交付范围

- 知乎站内问题池采集（当前实现采集外部文章，用于知乎 SEO 选题）
- 知乎回答发布
- 知乎图片/媒体上传
- 无人值守定时发布

参考 Easel 的 Playwright 持久化浏览器思路，但本项目使用 TypeScript/Node 实现，不引入额外 Python Runtime，也不改动现有小红书 MCP。
